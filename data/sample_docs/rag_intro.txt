Retrieval-Augmented Generation (RAG) is a technique that combines information retrieval with text generation to produce more accurate and grounded outputs from large language models. Traditional LLMs generate text purely from patterns learned during training, which can lead to hallucinations — confident but factually incorrect statements — especially when asked about niche topics, recent events, or private organizational data the model was never trained on.

RAG addresses this by adding a retrieval step before generation. When a user submits a query, the system first searches a knowledge base of documents for relevant passages. This is typically done by converting both the query and the documents into vector embeddings, then finding the documents whose embeddings are closest to the query embedding using cosine similarity or a similar distance metric. The most relevant passages are retrieved and inserted into the prompt as context.

The language model then generates its response conditioned on this retrieved context, rather than relying solely on its internal parametric knowledge. This has several benefits. First, it reduces hallucination because the model can ground its claims in actual retrieved text rather than inventing facts. Second, it allows the system to answer questions about information that was never part of the model's training data, such as internal company documents or very recent news. Third, it makes outputs more verifiable, since each claim can in principle be traced back to a specific source passage.

A typical RAG pipeline consists of several stages. Ingestion involves collecting documents and splitting them into smaller chunks, since embedding models have limited context windows and smaller chunks improve retrieval precision. Embedding involves converting each chunk into a dense vector representation using a model such as Sentence-BERT or OpenAI's embedding models. Indexing involves storing these vectors in a vector database such as FAISS, Pinecone, Weaviate, or Postgres with the pgvector extension, which allows for fast approximate nearest-neighbor search. Retrieval involves embedding the incoming query and searching the index for the top-k most similar chunks. Generation involves passing the retrieved chunks along with the original query to a language model, which produces the final answer.

One of the key challenges in building a production RAG system is choosing the right chunk size. If chunks are too large, irrelevant information gets mixed in with relevant information, diluting retrieval precision. If chunks are too small, important context may be split across multiple chunks, making it harder for the retriever to find complete, coherent information. Overlapping chunks — where consecutive chunks share a portion of text — can help mitigate this by ensuring that information near chunk boundaries is not lost entirely.

Another challenge is hallucination even within RAG systems. Even when relevant context is retrieved and provided to the model, the model may still generate claims that are not actually supported by that context, either by misreading the retrieved text or by blending it with its own parametric knowledge. This has led to research into verification layers that check whether generated claims are actually entailed by the retrieved source passages, sometimes using a second model call or a natural language inference model to score the faithfulness of each generated sentence against its cited source.
